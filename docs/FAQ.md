# 常见问题

## 概念类

### 定位测试成功，是不是说明高血压通知已经开通了？

**不是。** 这是本项目最想澄清的一点。

定位模拟只改变 iPhone 报告的地理坐标。高血压通知是否可用，取决于：

* 你的 Apple Watch 机型
* watchOS 与 iOS 版本
* 配对 iPhone 的区域设置与 Apple ID 所属地区
* 你是否满足医疗适用条件（22 岁以上、未确诊高血压、非妊娠期、腕部检测开启）

**唯一可信的判断依据是 iPhone 健康 App 里那张卡片的状态。** 工具会在每一处输出
反复提醒这一点，而且有自动化测试守着，不允许出现"已开通"这类断言。

### 我把定位切到香港，是不是就能用香港的健康功能了？

不能。功能区域由 **Apple ID 所属地区与 iPhone 区域设置**决定，跟 GPS 坐标无关。
把 GPS 改到香港不会让功能变成可用，也无法用来验证区域可用性。

四个地区预设只用于**定位链路测试**，不是区域解锁工具。

### 为什么不让我自己输入经纬度？

第一版刻意只给四个固定预设。原因有两个：需求就是这么定的；更少的自由度意味着
更小的误用空间。

### 为什么中国大陆不在预设里？

中国大陆尚未上线该功能（仍在等待监管批准）。中国香港在首发批次中已可用，
所以预设里有"中国香港"而没有大陆。这是两个不同的地区，要分开看。

### 我 20 岁 / 我已确诊高血压 / 我在妊娠期，能帮我绕过吗？

不能，而且这是 Apple 的**医疗设计边界**，不是我们的技术限制。

该功能面向 22 岁以上、既往未诊断高血压、非妊娠期人群。已确诊者的正确做法是
血压记录与医生随访，而不是这套筛查提醒。任何声称"能绕过"的工具都在害你。

工具会如实报告阻断项，并说明原因。

### 检查全绿了，为什么还是不告诉我"能用"？

因为工具**没有能力**知道。它无法查询你的手表型号、系统版本、健康状态——这些
只能由你填写。即使全部填对，功能是否真的在运行也只有健康 App 知道。

所以结论只有三种：机型不支持 / 资格条件不满足 / **需要你自己去核验**。
没有第四种。

## 安装与运行类

### `env` 显示引擎不可用怎么办？

先在 Windows 上装好旧引擎：

```bash
pip install "git+https://github.com/YEZH0/ios-location-studio.git@fix/windows-stabilization"
```

或者手动启动引擎，然后指定地址：

```bash
python -m assistant --engine-url http://127.0.0.1:8899 env
```

### 提示"不支持的平台：Linux"

本助手只支持 Windows 与 macOS。定位引擎本身不支持 Linux（usbmux 与 DVT 依赖
系统的 USB 栈），所以助手也不假装支持。

### `devices` 找不到手机

按顺序排查：

1. 用的是**数据线**吗？Wi-Fi 连接不行。
2. 手机解锁了吗？
3. 手机上有没有弹"信任此电脑"？点了信任吗？
4. 开发者模式开了吗？（设置 → 隐私与安全性 → 开发者模式）
5. 换一根线 / 换一个 USB 口试试。

`inventory.error` 字段会带出底层原因，用 `devices --json` 看。

### 检测到多台设备，被拒绝了

这是有意的保护。助手不替你选设备，因为改错手机的代价比多插拔一次大。
只留一台手机再试。

### 端口 8899 被占用

`start` 时会自动在 8899–8903 之间找空闲端口。全被占用会明确报错。
用 `--engine-url` 指定一个已经在跑的引擎即可。

### Windows 终端中文乱码

```bash
set PYTHONIOENCODING=utf-8
chcp 65001
```

或直接用 Windows Terminal（默认 UTF-8）。

## 使用过程类

### `start` 之后手机没反应

看 `python -m assistant status` 的状态：

* `connecting` —— 引擎正在建隧道。DVT 首次连接可能几十秒。
* `active` —— 引擎已下发坐标。去 iPhone 地图确认蓝点。
* `error` —— 看 `error` 字段的真实原因。

`active` 但蓝点没动，通常是手机端条件不满足（未解锁、开发者模式、未信任）。

### 能持续多久？

默认 180 秒，可用 `--hold` 调整，限制在 60–1800 秒。

不允许 0 或无限长：挂着一个模拟定位，人走开了却忘了，是有实际风险的。
到时间会自动停止。

### 中途关掉终端会怎样？

**引擎会话可能不被清理。** 正确做法是先 `stop` 再关终端。
如果不小心直接关了，重新运行 `python -m assistant stop` 即可。

### `stop` 之后位置没恢复？

按 `stop` 输出的清单做：

1. 拔掉 USB 线（这会强制中断隧道）；
2. iPhone 打开「地图」，点定位按钮，确认蓝点回到真实位置；
3. 重启 iPhone 是最彻底的手段。

程序说"已停止"**不等于**手机上的位置一定恢复了。这就是为什么要你人工确认。

### 定位测试会影响健康 App 的功能状态吗？

不应该。定位和健康数据采集是两条独立路径。如果你发现功能状态变了，那和本工具
无关，请以健康 App 显示为准。

## 项目协作类

### 为什么有两个 Agent？

Windows 和 macOS 两套引擎已经完成了，但实现差异很大。让两个 Agent 各自负责自己的
平台，避免一个人在两个平台之间来回切换、互相踩踏。

* Windows Agent：`assistant/` 核心 + `windows/`
* Mac Agent：`macos/`（从 `main` 创建 `feat/macos`）

唯一的交界是 `docs/ADAPTER-CONTRACT.md`，双方都按这份契约来。

### Mac Agent 要做什么？

在 `macos/` 下提供一个监听 `127.0.0.1:8900` 的桥接进程，暴露五个 JSON 接口
（health / devices / simulate / stop / status）。然后：

```bash
python -m assistant --engine-url http://127.0.0.1:8900 check
```

能跑通就算接入完成。助手核心一行都不用改。

具体规格见 [ADAPTER-CONTRACT.md](ADAPTER-CONTRACT.md)。

### 为什么不直接把旧代码复制过来？

三个原因：

1. 旧项目要能独立发版，不能因为新项目就被绑死；
2. 复制会产生许可证污染——macOS 引擎是 GPL，复制进 MIT 目录会让整个项目变 GPL；
3. 复制粘贴的代码会立刻开始分叉，两边都要修同样的 bug。

### 能不能直接 `import` 旧项目的模块？

Windows 引擎是 MIT，法律上可以。但项目仍然选择 HTTP 调用，因为解耦更好。

**macOS 引擎绝对不行**——那是 GPL，`import` 会让 MIT 部分变成 GPL 衍生作品。
见 [LICENSE-BOUNDARY.md](LICENSE-BOUNDARY.md)。

### 为什么不提供 EXE / APP / DMG？

交付要求就是只发源码。另外打包 GPL 软件还有额外的合规义务（必须提供对应源码、
依赖通知等），本项目明确不承担也不发布二进制。

### 我想加第五个地区预设

需要维护者确认。第一版明确限定四个。如果确有需要，请提 issue 说明理由，
而不是直接提 PR 加代码。
