# 常见问题

## 概念类

### 定位测试成功，是不是说明高血压通知已经开通了？

**不是。** 这是本项目最想澄清的一点。

这里其实有三个互相独立的状态，任何一个都不能推断下一个：

| 状态 | 含义 | 谁能确认 |
|---|---|---|
| 引擎 `active` | 引擎建立了会话并下发了模拟请求 | 助手可读 |
| 手机地图位置 | 苹果地图里的蓝点是否真的到了测试点 | 只有你看手机 |
| 健康功能状态 | 健康 App 里的卡片是否存在 / 是否已完成设置 | 只有你在健康 App 里 |

`active` 连「手机采用了坐标」都证明不了——引擎只知道自己的请求发成功了。
而定位成功和功能可用之间更是**没有因果关系**。功能取决于：

* 你的 Apple Watch 机型
* watchOS 与 iOS 版本
* 配对 iPhone 的区域设置与 Apple ID 所属地区
* 你是否满足医疗适用条件（22 岁以上、未确诊高血压、非妊娠期、腕部检测开启）

**唯一可信的判断依据是 iPhone 健康 App 里那张卡片的状态。**
`start` 的历史版本曾打印「模拟定位在手机上生效」，那是误报，已改正。

### 我把定位切到香港，是不是就能用香港的健康功能了？

不能。功能区域由 **Apple ID 所属地区与 iPhone 区域设置**决定，跟 GPS 坐标无关。
把 GPS 改到香港不会让功能变成可用，也无法用来验证区域可用性。

四个地区预设只用于**定位链路测试**，不是区域解锁工具。

### 为什么不让我自己输入经纬度？

第一版刻意只给四个固定预设。原因有两个：需求就是这么定的；更少的自由度意味着
更小的误用空间。`wizard` 的阶段 4 也只接受 `us/hk/fr/jp` 四个值，
传别的会直接报错（有测试守着）。

### 为什么中国大陆不在预设里？

中国大陆尚未上线该功能（仍在等待监管批准）。中国香港在首发批次中已可用，
所以预设里有"中国香港"而没有大陆。这是两个不同的地区，要分开看。

### 我 20 岁 / 我已确诊高血压 / 我在妊娠期，能帮我绕过吗？

不能，而且这是 Apple 的**医疗设计边界**，不是我们的技术限制。

该功能面向 22 岁以上、既往未诊断高血压、非妊娠期人群。已确诊者的正确做法是
血压记录与医生随访，而不是这套筛查提醒。任何声称"能绕过"的工具都在害你。

向导会在阶段 0 直接停下并拒绝进入定位阶段（代码里还有第二道校验），
**不是**提示一句就放行。

### 检查全绿了，为什么还是不告诉我"能用"？

因为工具**没有能力**知道。它无法查询你的手表型号、系统版本、健康状态——这些
只能由你填写。即使全部填对，功能是否真的在运行也只有健康 App 知道。

所以结论只有三种：机型不支持 / 资格条件不满足 / **需要你自己去核验**。
没有第四种。

## 向导（wizard）类

### 为什么不直接 `start`，非要走 wizard？

`start` 能做到的只有「把坐标发出去」。它没法保证三件事发生了：
你改动前的位置是真实的、蓝点在手机上真的动了、你完成后把位置恢复回来了。

`wizard` 把这三件事变成必须回答的问题。**手动路径仍然可用**，
但那就得你自己保证顺序。

### 没有终端交互，AI Agent 怎么驱动向导？

非交互调用时向导**只报告当前阶段，不会自己往下走**：

```bash
python -m assistant wizard --json                      # 看当前要做什么
python -m assistant wizard --answer confirmed --json    # 提交用户的确认
python -m assistant wizard --status --json              # 看进度
```

每次 `--answer` 会返回 `outcome` / `exit_code` / `next`。`exit_code` 为
`0` 继续、`1` 被阻断（解决后重复同一命令）、`3` 用户放弃。
完整说明见仓库根目录的 [AGENTS.md](../AGENTS.md)。

### 进度存在哪里？会不会存我的健康信息？

`.whc-wizard-state.json`（默认在当前目录）。里面**只有**流程位置和你的自述结论：

* 有：走到哪一步、选了哪个地区预设、地图动了没、健康 App 看到什么、位置恢复了没；
* **没有**：年龄、是否确诊、是否妊娠、经纬度、设备序列号。这些只在内存里传给
  兼容性检查，不落盘。

随时可以 `python -m assistant wizard --reset` 删掉。

### 中途 Ctrl+C / 关掉终端会怎样？

向导会尝试停止会话，然后打印恢复步骤和退出码（Ctrl+C 为 130）。
如果引擎此时已经不可达，它会明确说「停止失败，请手动运行 `python -m assistant stop`」，
不会假装停好了。

进度会保留，`python -m assistant wizard` 可以接着走。

### 会话到期了，算测试失败吗？

不算。到时间自动停止是**正常结束**。会话剩余时间在阶段 6 会显示出来，
如果你在健康 App 里操作超过了剩余时间，向导只会记录「会话已到期」，
不会把测试标成失败。

## 安装与运行类

### `env` 显示引擎不可用怎么办？

先在 Windows 上装好旧引擎：

```bash
pip install "git+https://github.com/YEZH0/ios-location-studio.git@fix/windows-stabilization"
```

或者手动启动引擎，然后指定地址（`--engine-url` 要写在子命令之前）：

```bash
python -m assistant --engine-url http://127.0.0.1:8899 env
```

### 提示"不支持的平台：Linux"

本助手只支持 Windows 与 macOS。定位引擎本身不支持 Linux（usbmux 与 DVT 依赖
系统的 USB 栈），所以助手也不假装支持。

### `devices` 找不到手机

按顺序排查：

1. 用的是**数据线**吗？Wi-Fi 连接不行。
2. 手机解锁了吗？
3. 手机上有没有弹"信任此电脑"？点了信任吗？
4. 开发者模式开了吗？（设置 → 隐私与安全性 → 开发者模式）
5. 换一根线 / 换一个 USB 口试试。

`inventory.error` 字段会带出底层原因，用 `devices --json` 看。
**设备不可见时向导不会下发任何坐标**（这是有意的，不是卡住了）。

### 检测到多台设备，被拒绝了

这是有意的保护。助手不替你选设备，因为改错手机的代价比多插拔一次贵。
只留一台手机再试。

### 端口 8899 被占用

`start` 时会自动在 8899–8903 之间找空闲端口。全被占用会明确报错。
用 `--engine-url` 指定一个已经在跑的引擎即可。

### Windows 终端中文乱码

```bash
set PYTHONIOENCODING=utf-8
chcp 65001
```

或直接用 Windows Terminal（默认 UTF-8）。

## 使用过程类

### `start` 之后手机没反应

先看 `python -m assistant status`：

* `connecting` —— 引擎正在建隧道。DVT 首次连接可能几十秒。
* `active` —— 引擎已下发坐标。**这不代表手机采纳了**，去 iPhone 地图确认蓝点。
* `error` —— 看 `error` 字段的真实原因。

### 地图蓝点没动，怎么办？

按顺序来，前一步有效就不做后面的：

1. 确认是数据线，换线或换 USB 口；
2. 确认手机已解锁、没有待确认的「信任此电脑」弹窗；
3. 确认「定位服务」总开关打开，地图允许定位 + 精确位置；
4. `python -m assistant status` 看会话是否还是 `active`；
5. 地图里再点一次定位按钮（别盯着旧画面）；
6. 把地图从后台完全划掉再打开。

以上都无效、且你同意时，才可以试**关闭「定位服务」总开关约 10 秒再打开**。
注意这可能让当前模拟失效（引擎仍显示 active，但手机已不再采用模拟坐标）。

**不要靠反复 `start` 硬试**：那不会改变手机端的采纳条件。

### 能持续多久？

默认 180 秒，可用 `--hold` 调整，实际范围 **60–180 秒**。

上限是引擎的硬约束：`POST /api/simulate` 对 `hold_seconds > 180` 直接返回
HTTP 422。请求值被夹到区间时，助手会明确告诉你实际生效的秒数，不会静默改写。

不允许 0 或无限长：挂着一个模拟定位、人走开了却忘了，是有实际风险的。

### 中途关掉终端会怎样？

**引擎会话可能不被清理。** 正确做法是先 `stop` 再关终端。
如果已经关了，重新运行 `python -m assistant stop` 即可。

用 `wizard` 的话，Ctrl+C 会自动尝试清理（如果引擎还在线）。

### `stop` 之后位置没恢复？

先分清两件事：`stop` 只保证**引擎不再下发坐标**，它看不到你手机里的定位缓存，
所以它无法声称「已恢复」。

按顺序来，**前一步有效就不必做后面的**：

1. 打开苹果地图，点一下定位按钮 —— 多数情况到这里就恢复了；
2. 还在测试点：拔掉 USB 数据线，确认 `status` 显示 `idle`；
3. 还没恢复：关闭「定位服务」总开关约 10 秒再打开，重开地图确认；
4. 还没恢复：重启 iPhone 再看一次。

**关于第 3 步：** 关闭定位服务确实能清空缓存并重启定位服务，但它不是所有人都必须做的
前提条件。它会打断正在导航、正在记录轨迹的 App，**也**可能让当前模拟会话彻底失效。
历史版本把它写成「不关 10 秒就恢复不了」，属于没有依据的绝对化表述，已改正。

如果 4 步都做完蓝点还在原地，先 `python -m assistant stop` 再来一遍，
并检查是不是还有别的调试工具/会话在占用同一台设备。

实在恢复不了就如实记为「未恢复」（`wizard --answer unresolved`），
不要把它当成「已经好了」。

### 定位测试会影响健康 App 的功能状态吗？

不应该。定位和健康数据采集是两条独立路径。如果你发现功能状态变了，那和本工具
无关，请以健康 App 显示为准。

### 健康 App 里找不到「高血压通知」卡片

**这不是单一原因，助手也无法远程判定。** 可能项：

* iOS / watchOS 版本低于该功能要求；
* 手表型号不在 Apple 官方支持范围内（大致为 Series 9 及后续、Ultra 2 及后续，以官方页面为准）；
* 配对 iPhone 的区域设置或 Apple ID 所属地区尚未开放；
* 系统刚更新完，卡片还没刷新出来——重启 iPhone 与手表再看；
* 健康核对清单在不同 iOS 版本/语言下位置和名称略有差异，可以在健康 App 里搜「高血压」。

逐项核对，**不要**断定是某一个原因，也不要用改地区、改账号的方式去绕过。

官方依据：<https://support.apple.com/en-us/117296> ·
<https://www.apple.com/watchos/feature-availability/>

### 卡片设置完成了，多久能看到效果？

首次提醒需要 **30 天数据窗口**，其中至少 14 天有效数据。需要每天正常佩戴（含睡眠）。
短期内没有任何提醒是**正常**的。

「设置完成」不等于「已生效」，也不等于「已验证可用」。这两件事只有时间能回答。

## 项目协作类

### 为什么有两个 Agent？

Windows 和 macOS 两套引擎已经完成了，但实现差异很大。让两个 Agent 各自负责自己的
平台，避免一个人在两个平台之间来回切换、互相踩踏。

* Windows Agent：`assistant/` 核心 + `windows/` + 公共文档
* Mac Agent：`macos/`

唯一的交界是 [ADAPTER-CONTRACT.md](ADAPTER-CONTRACT.md)，双方都按这份契约来。

### Mac Agent 要做什么？

在 `macos/` 下提供一个监听 `127.0.0.1:8900` 的桥接进程，暴露五个 JSON 接口
（health / devices / simulate / stop / status）。然后：

```bash
python -m assistant --engine-url http://127.0.0.1:8900 check
```

能跑通就算接入完成，助手核心一行都不用改。

**另外**：`wizard` 的阶段 id 与 `--answer` 取值是跨平台共享契约
（见 `assistant/wizard.py` 的 `STAGES`），Mac 侧只需保证五个 HTTP 接口行为一致，
向导本身不用重写。

### 为什么不直接把旧代码复制过来？

三个原因：

1. 旧项目要能独立发版，不能因为新项目就被绑死；
2. 复制会产生许可证污染——macOS 引擎是 GPL，复制进 MIT 目录会让整个项目变 GPL；
3. 复制粘贴的代码会立刻开始分叉，两边都要修同样的 bug。

### 能不能直接 `import` 旧项目的模块？

Windows 引擎是 MIT，法律上可以。但项目仍然选择 HTTP 调用，因为解耦更好。

**macOS 引擎绝对不行**——那是 GPL，`import` 会让 MIT 部分变成 GPL 衍生作品。
见 [LICENSE-BOUNDARY.md](LICENSE-BOUNDARY.md)。

### 为什么不提供 EXE / APP / DMG？

交付要求就是只发源码。另外打包 GPL 软件还有额外的合规义务（必须提供对应源码、
依赖通知等），本项目明确不承担也不发布二进制。

### 我想加第五个地区预设

需要维护者确认。第一版明确限定四个。如果确有需要，请提 issue 说明理由，
而不是直接提 PR 加代码。

### 想改向导的阶段划分 / 新增回答值

这是**跨平台共享契约**。提 issue 对齐后再动，Windows 与 Mac 两侧要同步改，
否则两边流程会不一致。
