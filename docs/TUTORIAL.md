# 使用教程（0–8 阶段）

面向第一次使用的人：从零开始，走完一次**包含手机上人工确认**的完整测试与核验。

> 只想快点跑起来 → [QUICKSTART.md](QUICKSTART.md)
> 把仓库链接交给 AI Agent → 让它先读 [../AGENTS.md](../AGENTS.md)

---

## 为什么要有阶段

定位引擎能改的是「手机报告给 App 的坐标」。它改不了另外两件更关键的事：
**蓝点在手机上到底动没动**、**健康 App 里那张卡片到底是什么状态**。
这两件只有你能回答。

所以本教程按 9 个阶段推进，每个阶段都停下来等你确认。跳过确认节点带来的
不是「省事」，而是「以为做完了，其实什么都没验证」。

| 阶段 | 名称 | 谁来做 |
|---|---|---|
| 0 | 安全与资格告知 | 你读，你确认 |
| 1 | 环境与引擎 | 助手检查 |
| 2 | USB 连接 | 你插线，助手检查 |
| 3 | 真实位置基线 | **你在手机上确认** |
| 4 | 地区测试预设 | **你选，助手下发** |
| 5 | 手机端位置验证 | **你看地图回答** |
| 6 | 健康 App 核验 | **你在健康 App 里看** |
| 7 | 停止与恢复 | **你确认位置回来了** |
| 8 | 分项汇报 | 助手汇总 |

交互式一次跑完：

```bash
python -m assistant wizard
```

也可以按本文手动执行每条命令——顺序一样，命令在每一节里。

## 准备：你需要什么

| 项目 | 要求 |
|---|---|
| 电脑 | Windows 10/11 或 macOS（不支持 Linux） |
| Python | 3.11 或以上 |
| iPhone | 用 USB 数据线连接，**不是 Wi-Fi** |
| iPhone 设置 | 已解锁、已「信任此电脑」、开发者模式已开启 |
| 已完成定位引擎 | Windows：`fix/windows-stabilization`；macOS：`feat/macos-iap2` |
| Apple Watch | 已与这台 iPhone 配对 |

> 开发者模式需要你自己在 iPhone 上开启（设置 → 隐私与安全性 → 开发者模式）。
> 本工具**不会**替你做这件事，也不建议为了跑测试去降低设备安全设置。

## 阶段 0 · 安全与资格告知

先把话说明白，再决定要不要继续：

* 本工具会**临时改变 iPhone 报告的地理位置**。依赖位置的 App（地图、外卖、打车、打卡）会受影响；
* 只能用在**你本人拥有**、或**已获得机主明确授权**的设备上；
* 高血压通知有 Apple 设定的医学适用条件（22 岁以上、既往未诊断高血压、非妊娠期、腕部检测开启）。
  不满足时本工具会如实告诉你，**不提供任何变通方案**；
* 区域可用性由 Apple ID 所属地区与 iPhone 区域设置决定，改 GPS 改变不了它。

资格核对按 Apple 官方条件填写，检查结论只有三种：

```bash
python -m assistant check \
  --watch series10 --watchos 26.1 --ios 26.1 \
  --age 30 --no-hypertension --no-pregnant --wrist-detection
```

```
结论：机型与资格条件均满足，但功能的实际状态仍然未知。
```

机型 id 不知道写什么先看 `python -m assistant families`。

**注意读法：** `[通过]` 表示「这一项没发现问题」，不表示「功能已开通」。
结论里**没有**「已开通」这个取值——这是刻意从类型层面去掉的。

不确定就留空。结论会变成 `needs_manual_verification`（仍需你自己核验），流程照常继续。

**资格不满足时**（年龄不够 / 已确诊 / 妊娠期 / 腕部检测关闭），向导会停在阶段 0 并拒绝进入定位阶段。
这是 Apple 的医疗设计边界，不是技术限制。只读检查与说明仍然可用：

```bash
python -m assistant compat --help
python -m assistant guide
```

## 阶段 1 · 环境与引擎

```bash
python -m assistant env
```

正常输出：

```
── 运行环境 ───────────────────────────────────────
平台：Windows（windows）
引擎：windows-dvt · 在线
地址：http://127.0.0.1:8899
```

引擎显示「不可用」时，Windows 上最常见的原因是旧版引擎没装：

```bash
pip install "git+https://github.com/YEZH0/ios-location-studio.git@fix/windows-stabilization"
```

或者你已经手动启动了引擎，直接指过去（`--engine-url` 要写在子命令**之前**）：

```bash
python -m assistant --engine-url http://127.0.0.1:8899 env
```

> 助手不会自动下载并运行任何远程脚本，也不会改动不相关的系统设置。

## 阶段 2 · USB 连接

1. 用**数据线**连接 iPhone（只能充电的线不行）；
2. 解锁手机，保持屏幕点亮；
3. 手机上弹「要信任此电脑吗」→ 点「信任」→ 输入锁屏密码；
4. 只连**一台**手机。

```bash
python -m assistant devices
```

```
── USB 设备 ───────────────────────────────────────
发现 1 台设备：
  1. 我的 iPhone · iOS 26.1 · iPhone17,3
※ 未输出设备标识符；助手不采集、不上传序列号。
```

检测到 0 台 → **停在这一步**排查，不要往下发坐标：

* 换一根线 / 换一个 USB 口；
* 确认没有用 Wi-Fi 连接；
* 确认手机已解锁、已点信任；
* 引擎提示需要开发者模式时，自己到「设置 → 隐私与安全性 → 开发者模式」开启并重启。

检测到多台 → 助手会拒绝继续。这不是 bug，是防止改错手机。

## 阶段 3 · 真实位置基线（关键）

**在改动任何东西之前，先确认手机现在显示的是真实位置。**
没有这个对照，后面就无法判断蓝点是不是真的动了。

在 iPhone 上：

1. 「设置 → 隐私与安全性 → 定位服务」——总开关必须打开；
2. 在同一页面找到「地图」，确认允许定位、并允许「精确位置」；
3. 打开苹果地图，点一下右下角的定位按钮；
4. 确认蓝点就在你**实际待的地方**（家 / 公司 / 学校），不是在别处。

确认后才继续：

```bash
python -m assistant wizard --answer confirmed
```

蓝点不在真实位置时**先别继续**：解决定位权限，或等地图完成首次定位。
这里回答「还没确认」是有效回答，向导不会推进，也不会发任何坐标。

## 阶段 4 · 地区测试预设

```bash
python -m assistant regions      # 先看四个预设
```

| id | 地区 | 城市 | 坐标 |
|---|---|---|---|
| `us` | 美国 | 纽约 · 时代广场 | 40.7580, -73.9855 |
| `hk` | 中国香港 | 香港 · 中环 | 22.2819, 114.1588 |
| `fr` | 法国 | 巴黎 · 埃菲尔铁塔 | 48.8584, 2.2945 |
| `jp` | 日本 | 东京 · 涩谷十字路口 | 35.6595, 139.7005 |

**由你自己选**，助手不会替你默认。选定后下发：

```bash
python -m assistant wizard --answer hk
# 等价的手动命令：python -m assistant start --region hk
```

```
── 定位测试 · 中国香港 · 香港 · 中环 ──────────────
坐标（固定预设）：22.2819, 114.1588

引擎已接受请求，会话状态：active（剩余约 180 秒）。

现在请在 iPhone 上确认：
  1. 打开「地图」App，点一下右下角定位按钮，让它重新取一次位置。
  2. 看蓝点是否真的到了上面这个坐标。
```

**这句话要读清楚：** 「引擎已接受请求」只代表引擎认为请求下发成功。
它不知道手机有没有采纳。历史版本这里写「模拟定位在手机上生效」，属于误报，已改正。

> ⚠️ **定位 ≠ 区域可用性。** 改 GPS 不会让健康功能变成另一个地区可用。

会话默认保持 180 秒（可用 `--hold` 调整，实际范围 60–180 秒——上限是引擎的硬约束）。
到时间自动停止是**正常结束**，不是失败。

## 阶段 5 · 手机端位置验证（关键）

保持 USB 连接，回到 iPhone：

1. 打开苹果地图，**点一下定位按钮**让它重新取位置（不要看旧画面）；
2. 看蓝点：在测试点，还是仍在你的真实位置？

然后如实回答：

```bash
python -m assistant wizard --answer moved       # 蓝点到了测试点
python -m assistant wizard --answer not_moved   # 蓝点没动
python -m assistant wizard --answer unsure      # 没看清 / 不确定
```

「不确定」是有效回答。**不要为了走完流程而猜**——猜出来的「已移动」会让你后面
所有判断都建立在错误前提上。

### 蓝点没动怎么办

按顺序排查，前一步有效就不做后面的：

1. 确认是**数据线**连接，换一根线或换一个 USB 口；
2. 确认手机已解锁，屏幕上没有待确认的「信任此电脑」弹窗；
3. 确认「定位服务」总开关打开，地图允许定位和精确位置；
4. `python -m assistant status` 看会话是否还是 `active`；
5. 地图里再点一次定位按钮；
6. 把地图 App 从后台完全划掉再打开（后台挂起时可能不刷新）。

以上都不行、且你同意时，才可以尝试**关闭「定位服务」总开关约 10 秒再打开**。
注意：这一步可能让当前模拟失效（引擎仍显示 active，但手机已不再采用模拟坐标）。
它是条件性排查手段，**不是所有设备都必须执行的步骤**。

## 阶段 6 · 健康 App 核验（关键，且与定位结果无关）

无论定位成不成功，这一步都要做。功能状态和定位结果没有因果关系。

```bash
python -m assistant guide
```

在 iPhone 上：

1. 打开「健康」App → 右上角头像；
2. 进入「健康核对清单」（Health Checklist）；
3. 找到「高血压通知」（Hypertension Notifications）并点进去；
4. 按系统提示**如实**填写年龄、是否曾被诊断高血压、是否妊娠；
5. 完成引导，点「完成」；
6. 确认「腕部检测」已开启（Watch App → 密码 → 腕部检测）。

然后如实回报你看到的画面：

```bash
python -m assistant wizard --answer setup_done           # 卡片存在，已完成设置
python -m assistant wizard --answer card_absent          # 找不到卡片
python -m assistant wizard --answer eligibility_blocked  # 系统说我不符合条件
python -m assistant wizard --answer not_checked          # 还没去看
```

回答之后，向导会**立刻停止定位会话**，不需要你记得再去跑 `stop`。

### 找不到「高血压通知」卡片

**这不是单一原因**，助手也无法远程判定。可能项：

* iOS / watchOS 版本低于该功能要求；
* 手表型号不在 Apple 官方支持范围内（大致为 Series 9 及后续、Ultra 2 及后续，以官方页面为准）；
* 配对 iPhone 的区域设置或 Apple ID 所属地区尚未开放该功能；
* 系统刚更新完，卡片还没刷新出来——重启 iPhone 与手表再看；
* 健康核对清单在不同 iOS 版本/语言下位置和名称略有差异，可以在健康 App 里搜「高血压」。

逐项核对，**不要**因为卡片不存在就断定是某一个原因，也不要通过改地区、改账号去绕过。
官方依据：<https://support.apple.com/en-us/117296> ·
<https://www.apple.com/watchos/feature-availability/>

### 「已完成设置」之后

设置完成 ≠ 已生效：

* 需要每天正常佩戴（含睡眠），**首次提醒需要 30 天数据窗口**，其中至少 14 天有效数据；
* 短期内没有任何提醒是正常的；
* 功能是否真的在运行，以健康 App 中那张卡片的状态为准；
* 收到提醒的正确做法：用独立血压计连续测量 7 天并咨询医生。这是筛查提醒，不是诊断。

## 阶段 7 · 停止与恢复真实位置（关键）

会话在阶段 6 结束时已经停止。但**手机上的位置是否回来，助手看不到**，只能由你确认。

```bash
python -m assistant stop        # 手动路径；向导路径会自动执行等价操作
```

```
── 已停止定位 ─────────────────────────────────────
模拟已停止，引擎不再下发坐标。但手机上的真实位置有没有回来，助手看不到——
需要你在苹果地图里确认。

按顺序确认（前一步有效，就不必做后面的）：
  1. 打开 iPhone「地图」App，点一下右下角的定位按钮。
     → 蓝点回到你实际所在的位置。
  2. ［蓝点仍停在测试点时］拔掉 USB 数据线，并确认会话已停止…
  3. ［拔线后仍然没有恢复时］关闭「定位服务」总开关，等约 10 秒再打开…
  4. ［关闭定位服务后仍然没有恢复时］重启 iPhone…
  5. 回到健康 App，确认功能状态与测试前一致。
```

然后如实回答：

```bash
python -m assistant wizard --answer restored        # 蓝点回到真实位置
python -m assistant wizard --answer not_restored    # 还在测试点，继续排查
python -m assistant wizard --answer unresolved      # 试过仍不对，如实记为未恢复
```

> **关于「关闭定位服务 10 秒」**
> 这一步确实能清空定位缓存并重启定位服务，但它是排查链路里的一环，不是普适前提。
> 已经恢复的人做这一步只是白白打断导航、轨迹记录等正在用定位的 App。
> 历史版本写成「不关 10 秒就一定恢复不了」，已改正。

选了 `unresolved` 也不会把你困住：向导会以 `restore_result: not_confirmed`
如实收尾，并在报告里写明「可能仍显示测试点位置」。

## 阶段 8 · 分项汇报

最后一步 `--answer restored` 答完会直接打印报告，不用再单独查一次。

```bash
python -m assistant wizard --answer restored
```

```
── 分项报告 ───────────────────────────────────────
  引擎：在线
  模拟请求：引擎已接受过模拟请求（active），测试点 hk；会话已停止
  手机地图位置：用户确认蓝点已移动到测试点
  健康 App 功能：用户自述已完成设置（不等于已生效）
  真实位置恢复：用户确认已恢复真实位置

第 3–5 项（地图、健康 App、位置恢复）均为用户自述，助手无法独立验证。
本报告不构成「高血压通知已开通 / 已生效」的结论。
```

「引擎已接受过……；会话已停止」这个组合是刻意的：报告通常在流程末尾生成，
那时会话早就停了，只写 active 会被读成「现在还在跑」。

汇报时逐条转述，「未知」就写未知。**不要**合成一句「全部成功」。

## 出问题的时候

| 现象 | 该怎么办 |
|---|---|
| 引擎不可用 | 装/启动引擎；或用 `--engine-url` 指向已运行实例 |
| 找不到手机 | 数据线 / 解锁 / 信任 / 换口；设备可见前不会发坐标 |
| 多台设备被拒 | 只留一台 |
| 蓝点没动 | 阶段 5 的排查顺序，不要靠重复 `start` 硬试 |
| 会话到期 | 正常结束，继续健康 App 核验与恢复确认 |
| 找不到健康卡片 | 列可能原因 + 官方链接，不下结论 |
| 中途关掉终端 | 重新跑 `python -m assistant stop`，再按阶段 7 确认位置 |
| 恢复不了 | 走完 4 级排查，如实记为未恢复，不要写「已恢复」 |
| 想推翻重来 | `python -m assistant wizard --reset` |

更多问答见 [FAQ.md](FAQ.md)。

## 完整命令参考

| 命令 | 说明 |
|---|---|
| `wizard` | 0–8 阶段引导（每步等确认，可中断可继续） |
| `wizard --plan` / `--status` / `--reset` | 看流程 / 看进度 / 清空进度 |
| `wizard --answer <value> [--stage <id>]` | 提交某一阶段的确认 |
| `env` | 平台 + 引擎 |
| `devices` | USB 设备 |
| `regions` | 四个地区预设 |
| `families` | 机型选项 |
| `compat --watch …` | 只做兼容性检查 |
| `check` | 完整检查（默认命令） |
| `start --region hk [--hold 180]` | 启动定位测试 |
| `stop` | 停止 + 分级恢复步骤 |
| `status` | 当前会话 |
| `guide` | 健康 App 核验指引 |

全局：`--engine-url <url>` 指定运行中的引擎（写在子命令之前）。
所有命令加 `--json` 输出机器可读结果。

## 常见误用

| 误用 | 为什么不对 |
|---|---|
| 「start 说 active，位置就改好了」 | active 只代表引擎把请求发出去了。手机是否采用，看地图。 |
| 「定位到香港了，说明香港功能可用」 | 定位与区域可用性无关。区域看 Apple ID 和 iPhone 区域设置。 |
| 「check 全绿，功能已开通」 | 全绿只代表没发现阻断项。是否开通只能看健康 App。 |
| 「卡片不存在，肯定是地区问题」 | 版本、型号、地区、刷新、菜单差异都可能。逐项核对，别下单一结论。 |
| 「必须关定位服务 10 秒才能恢复」 | 它是排查链路的一环，不是普适前提。 |
| 「我 20 岁，帮我绕过年龄限制」 | Apple 的医疗适用边界，工具不提供变通。 |
| 「帮我把坐标设成任意经纬度」 | 只提供四个固定预设，这是刻意的限制。 |
| 「把它打包成 EXE 方便分发」 | 本项目只发布源码，不提供打包产物。 |
