# 使用教程

面向第一次使用的人，从零到完成一次完整的测试与核验。

---

## 准备：你需要什么

| 项目 | 要求 |
|---|---|
| 电脑 | Windows 10/11 或 macOS |
| Python | 3.11 或以上 |
| iPhone | 用 USB 数据线连接，**不是 Wi-Fi 连接** |
| iPhone 设置 | 已解锁、已"信任此电脑"、开发者模式已开启 |
| 已完成的定位引擎 | Windows：`fix/windows-stabilization` 分支；macOS：`feat/macos-iap2` 分支 |
| Apple Watch | 已与这台 iPhone 配对 |

> 开发者模式需要你自己在 iPhone 上开启（设置 → 隐私与安全性 → 开发者模式）。
> 本工具**不会**替你做这件事，也不建议为了跑测试去降低设备安全设置。

---

## 第一步：安装助手

```bash
git clone https://github.com/YEZH0/watch-hypertension-assistant.git
cd watch-hypertension-assistant
pip install -e ".[dev]"
```

运行时零第三方依赖。`[dev]` 只是测试用的 `pytest`、`ruff`。

## 第二步：确认引擎在线

```bash
python -m assistant env
```

正常输出：

```
── 运行环境 ───────────────────────────────────────
平台：Windows（windows）
引擎：windows-dvt · 在线
地址：http://127.0.0.1:8899
```

如果显示"不可用"，按提示操作。Windows 上最常见的原因是旧版引擎没有安装：

```bash
pip install "git+https://github.com/YEZH0/ios-location-studio.git@fix/windows-stabilization"
```

也可以手动启动引擎后，用 `--engine-url` 直接指过去：

```bash
python -m assistant --engine-url http://127.0.0.1:8899 env
```

## 第三步：连上 iPhone，检查设备

用 USB 线连接，在手机上点"信任"。然后：

```bash
python -m assistant devices
```

```
── USB 设备 ───────────────────────────────────────
发现 1 台设备：
  1. 我的 iPhone · iOS 26.1 · iPhone17,3
※ 未输出设备标识符；助手不采集、不上传序列号。
```

**只连一台手机。** 检测到多台时助手会拒绝继续，避免改错设备。

## 第四步：兼容性检查

这一步判断你的**机型和系统**是否在 Apple 的支持范围内，并如实报告你不满足的
医疗适用条件。

```bash
python -m assistant check \
  --watch series10 \
  --watchos 26.1 \
  --ios 26.1 \
  --age 30 \
  --no-hypertension \
  --no-pregnant \
  --wrist-detection
```

机型 id 不知道写什么，先看列表：

```bash
python -m assistant families
```

输出示例：

```
── 前置检查 ───────────────────────────────────────
  [通过] 定位引擎可用：windows-dvt 0.1.0 @ http://127.0.0.1:8899
  [通过] USB 设备连接：发现 1 台设备

── 高血压通知兼容性 ────────────────────────────────
结论：机型与资格条件均满足，但功能的实际状态仍然未知。
  [通过] 机型：Apple Watch Series 10
  [通过] watchOS：26.1 ≥ 26.0
  ...
```

**注意读法：** `[通过]` 表示"这一项没发现问题"，不表示"功能已开通"。

如果你的手表是 SE，或者系统低于 watchOS 26，结论会是 `[阻断]`。这是真实结论，
不要试图绕过——硬件和系统版本改不了。

## 第五步：选择地区预设，启动定位测试

```bash
python -m assistant regions     # 先看四个预设
python -m assistant start --region hk
```

```
── 定位测试 · 中国香港 · 香港 · 中环 ──────────────
坐标（固定预设）：22.2819, 114.1588

※ 定位模拟改变的是手机报告的地理坐标；苹果的健康功能区域可用性取决于
  配对 iPhone 的区域设置与 Apple ID 所属地区，二者不是一回事。...

已启动，模拟定位在手机上生效（剩余约 180 秒）。
```

现在去 iPhone 上：

1. 打开「地图」App，确认蓝点已经到了香港中环；
2. 保持连接，不要拔线。

> 默认保持 180 秒。可加 `--hold 300` 调整，范围限制在 60–1800 秒。
> 不允许 0 或无限长——挂着一个模拟定位是有实际风险的。

## 第六步：停止并恢复真实位置

```bash
python -m assistant stop
```

```
── 已停止定位 ─────────────────────────────────────
定位已停止。请断开 USB 数据线，然后在 iPhone 的「地图」App 中点击定位按钮，
确认蓝点已回到你的真实位置。确认无误后再结束本次测试。

恢复确认清单：
  [ ] USB 数据线已断开，或引擎会话已完全退出。
  [ ] iPhone「地图」App 中的蓝点已回到真实位置。
  [ ] 健康 App 中的功能状态没有任何变化（定位测试不应影响它）。
```

**这三项必须自己确认。** 程序说"已停止"不等于手机上的位置一定恢复了。

## 第七步：在健康 App 里核验功能状态

```bash
python -m assistant guide
```

步骤摘要：

1. iPhone 打开「健康」App → 右上角头像
2. 进入「健康核对清单」
3. 找到「高血压通知」卡片
   - **卡片不存在** → 当前机型/系统/地区不满足条件，这就是结论
4. 按提示如实填写年龄、是否确诊高血压、是否妊娠
5. 完成引导，点「完成」
6. 确认「腕部检测」已开启

然后：

* 每天正常佩戴，**首次提醒需要 30 天数据窗口**（其中至少 14 天有效数据）；
* 短期内没有任何提醒是正常的；
* 功能是否真的在跑，以健康 App 中那张卡片的状态为准。

## 完整命令参考

| 命令 | 说明 |
|---|---|
| `env` | 平台 + 引擎 |
| `devices` | USB 设备 |
| `regions` | 四个地区预设 |
| `families` | 机型选项 |
| `compat --watch …` | 只做兼容性检查 |
| `check` | 完整检查（默认命令） |
| `start --region hk [--hold 300]` | 启动定位测试 |
| `stop` | 停止 + 恢复清单 |
| `status` | 当前会话 |
| `guide` | 健康 App 核验指引 |

全局：`--engine-url <url>` 指定运行中的引擎。

所有命令加 `--json` 输出机器可读结果。

---

## 常见误用

| 误用 | 为什么不对 |
|---|---|
| "定位到香港了，说明香港功能可用" | 定位与区域可用性无关。区域看 Apple ID 和 iPhone 区域设置。 |
| "check 全绿，功能已开通" | 全绿只代表没发现阻断项。是否开通只能看健康 App。 |
| "我 20 岁，帮我绕过年龄限制" | 这是 Apple 的医疗适用边界，工具不提供变通。 |
| "帮我把坐标设成任意经纬度" | 第一版只提供四个固定预设，这是刻意的限制。 |
| "把它打包成 EXE 方便分发" | 本项目只发布源码，不提供打包产物。 |
